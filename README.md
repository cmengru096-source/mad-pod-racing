# Mad Pod Racing · 连续碰撞预测与实时路径搜索

四辆赛车在同一条赛道上争抢检查点。每回合，每队为两辆车分别输出转向目标和推力。任意一辆先完成所有圈数，其队伍获胜。同队两车连续 100 回合未通过检查点会被淘汰。领跑车的路线既要考虑下一道弯，也要考虑被撞后速度会指向哪里。[赛题和规则](https://www.codingame.com/multiplayer/bot-programming/mad-pod-racing)

仓库包含可单独运行的 Python 物理模型与搜索实验。下文分别给出参考实现的实验数据和完整 C++ 双车策略的竞技场成绩。

## 快速运行

Python 3.10 或更新版本，只依赖标准库。以下命令在仓库根目录运行。

~~~sh
python search_demo.py
python -m unittest discover -s tests -v
~~~

## 物理引擎

普通回合转向最多 18°，首回合可自由定向。Gold 版控制器和本地裁判沿新朝向施加 0 到 100 的普通推力。Legend 允许最高 200，已晋级的同一份 v1.0 仍按 100 搜索。两车共用一次 650 推力的 BOOST。护盾在激活回合把质量从 1 提到 10，当回合及随后三个回合不能加速。每回合先处理运动轨迹，再把位置按 floor(x + 0.5) 取整，碰撞后的速度乘 0.85 后向零取整。

取两车的圆心差 r 和相对速度 u。接触时，圆心距离等于两车半径之和 800。

$$
r=p_B-p_A,\quad u=v_A-v_B,\quad \lVert r-tu\rVert^2=800^2.
$$

记 a = u·u、b = r·u、c = r·r − 800²。当两车尚未接触且正在靠近时，判别式 D = b² − ac。若 D ≥ 0，较小根可写为 t = c/(b + √D)，避免两个接近的浮点数相减。只有落在本回合剩余时长内的根才是事件。

碰撞时取从 A 指向 B 的单位法线 n。第一次法向冲量由相对速度和质量决定，第二次同向冲量最小为 120。两次冲量之和 J 用来更新速度。

$$
f=\frac{u\cdot n}{1/m_A+1/m_B},\quad J=f+\max(120,f),\quad v'_A=v_A-Jn/m_A,\quad v'_B=v_B+Jn/m_B.
$$

四车共有六对候选。先处理最早一次接触，再重算剩余时间里的碰撞。检查点沿运动线段检测，可识别同一回合从圆外穿入、再穿出的路线。[物理实现](physics.py) · [边界条件测试](tests/test_physics.py)

例如，两车在同一直线上，初始圆心位于 0 和 1100，速度为 +300 和 −300。半回合后相距 800，等质量对撞后交换速度，剩余半回合各自折返。回合结束时位置回到 0 和 1100，速度为 −255 和 +255。

过门边界会影响临界路线。公开的 Python 模型计入圆周相切，末段使用取整后的终点，且允许一段轨迹按顺序通过多个门。参赛 C++ 使用未取整的圆心线段，要求到门心的最近距离严格小于 600，每个碰撞分段最多记一门。恰好擦着半径 600 行驶时，两种实现可能给出不同结果。

## 局面评估与双车博弈

完整双车策略把领跑任务和拦截任务分开搜索。领跑车在第 5、9、12 个模拟回合分别计分，权重为 0.1、0.2、1。单个状态既考虑累计赛程和到检查点的直线距离，也估算沿当前速度滑行 2.55 回合后的距离。距检查点不足 2900 时，下一段赛道方向上的速度和朝向开始加分。这使搜索可以接受暂时更远、但出弯速度更好的路线。

拦截车先外推对方领跑车 50 回合，再用自身惯性、转向时间和加速度估算到各候选位置还差多少距离。设这个差值为 d，则选取使 t + max(0,d)/155 + max(0,−d)/1600 最小的交会时刻 t。即使赶不上任何候选位置，仍能选出代价最小的目标。拦截车评分奖励己方进度、惩罚对方进度，并计入与交会点的距离。己队长期没过关时，拦截车改为争取通过自己的下一检查点。对手使用启发式动作，预测不确定性主要来自对方何时转向、开盾或改变分工。

~~~mermaid
flowchart TD
  A[四车位置、速度、朝向与下一门] --> B[更新过门记录与双车分工]
  B --> C[预测对手轨迹与拦截点]
  C --> D[固定搭档基线，搜索领跑车计划]
  D --> E[固定领跑计划，搜索搭档计划]
  D -. 候选评分 .-> F[用四车连续碰撞仿真比较第 5、9、12 步]
  E -. 候选评分 .-> F
  E --> G[分配共享 BOOST，输出两车首步]
~~~

## 实时搜索

| 项目 | Python 单车实验 | C++ 双车竞技策略 |
| --- | --- | --- |
| 计划 | 12 步转向与推力，只执行第一步 | 每车 12 步；先固定队友计划优化领跑车，再用领跑计划优化搭档 |
| 候选 | 每步评估 80 条，保留 5 条优胜计划 | 每车保留 5 条；种子之外两次搜索分别最多 280、200 次迭代 |
| 延续与探索 | 上一回合计划左移；单点交叉、连续 1–3 步变异 | 左移暖启动，定期重新引入启发式计划和交叉；每次变异 1–4 个片段 |
| 目标 | 先比较能否完赛和完赛回合，再比较剩余赛程与速度 | 在同一套四车碰撞仿真里，按领跑、拦截或救场角色评价联合行动 |
| 预算 | 固定评估次数 | 从同一个回合起点累计计时，在 31 ms、53 ms 附近分别停止两次搜索，每 4 次迭代检查时钟 |

官方首回合上限为 1000 ms，常规回合为 75 ms。31 和 53 ms 是搜索截止点，并非实测耗时。固定大小的状态和计划数组、预计算赛段长度、每回合只计算一次拦截参考轨迹，减少了候选评估的重复工作。12 步是当前设置，增大深度会提高每次评估的成本，其净收益取决于固定预算下能探索多少候选。[实验搜索实现](search_demo.py)

## 实验数据

两个固定场景都使用种子 41。两种控制器使用相同物理模型、初始位置和检查点顺序。贪心策略每回合全速瞄准下一检查点。相向场景中，对手按惯性滑行。

| 场景 | 贪心完赛回合 | 搜索完赛回合 | 提前回合 | 观察 |
| --- | ---: | ---: | ---: | --- |
| 正面相向，单检查点 | 24 | 18 | 6 | 搜索在第一回合开盾，承担停推代价后仍更早通过 |
| 无对手，四检查点一圈 | 74 | 55 | 19 | 第 12 回合搜索的剩余路线反而更长，但最终出弯更快 |

在 Windows、Ryzen 7 5800H、CPython 3.12.8 上，以上两个场景各重复 5 次，每场重新用种子 41 初始化搜索器。用单调高精度时钟包裹每次 `Evolution.__call__`，共 365 次决策，P50 为 **11.71 ms**，P95 为 **20.36 ms**，最大值为 **30.13 ms**。这些测量仅覆盖本机的 Python 单车搜索调用。两个固定场景的指标是完赛回合数；对阵胜率见竞技场记录。

## 双车策略 A/B 对照

冻结 30 张赛道，其中 6 张沿用 Gold 官方失利的检查点布局，另有 12 张开发图和 12 张独立留出图。每张地图交换出生位，A、B 直接对阵两局，再分别用两个出生位对阵固定程序 R，共 180 局。R 与 A 同为 v1.0，因此两套设计使用同一种对手，留出组检验的是新地图上的表现。每局采用相同初态、三圈、最多 500 回合。实验沿用 Gold 普通推力上限 100，固定 12 步、280/200 次迭代。两版都运行独立的 C++ 进程，使用同一个本地裁判。

v2.0 在识别到对方拦截车挡在前方且距当前门小于 1500 时，把瞄点向空侧移动 450，给半径 600 的门留下 150 裕量。领跑车开盾要求未来 1–2 回合中某一步两车最近距离小于 850、径向逼近速度大于 300，且三回合惯性足以过门，或模拟显示不防撞会漏门。第一步威胁可主动开盾，仅第二步有威胁时交给搜索选择。避让优先，搭档沿用 v1.0。

| 版本 | 对 R 胜场 / 有效场次 | 平局 | 异常 / 计划场次 | 内部均值 ms | 端到端均值 ms | 端到端 P95 ms | 端到端最大 ms |
| --- | --- | --- | --- | --- | --- | --- | --- |
| v1.0 | 30/60（50.00%） | 0 | 0/60 | 15.65 | 15.92 | 17.55 | 26.97 |
| v2.0 | 41/60（68.33%） | 0 | 0/60 | 28.28 | 28.55 | 39.82 | 57.06 |

计时环境为 Windows 11、Ryzen 7 5800H、MinGW g++ 6.3.0（-O2）。胜率分母包含平局。任一程序出现技术错误时，该场不计有效胜率，异常另列。端到端时间从发送回合状态计到读完第二条动作。

另 60 场换位直战，v2.0 取 41 胜、19 负、0 平，另有 0 场技术异常。固定对手的地图配对得分以胜 1、平 0.5、负 0 计，要求两版在同地图、同出生位有有效结果，再对两个出生位取均值。
