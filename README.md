# Mad Pod Racing · 连续碰撞预测与实时路径搜索

四辆赛车在同一条赛道上争抢检查点。每回合，每队为两辆车分别输出转向目标和推力。任意一辆先完成所有圈数，其队伍获胜。同队两车连续 100 回合未通过检查点会被淘汰。领跑车的路线既要考虑下一道弯，也要考虑被撞后速度会指向哪里。[赛题和规则](https://www.codingame.com/multiplayer/bot-programming/mad-pod-racing)

仓库包含可单独运行的 Python 物理模型与搜索实验。下文分别给出参考实现的实验数据和完整 C++ 双车策略的竞技场成绩。

## 快速运行

Python 3.10 或更新版本，只依赖标准库。以下命令在仓库根目录运行。

~~~sh
python search_demo.py
python -m unittest discover -s tests -v
~~~

## 物理引擎

普通回合转向最多 18°，随后沿新朝向施加 0 到 100 的推力。首回合可自由定向。两车共用一次 650 推力的 BOOST。护盾在激活回合把质量从 1 提到 10，当回合及随后三个回合不能加速。回合内先处理完整的运动轨迹，最后把位置四舍五入为整数，速度乘 0.85 后向零取整。

令 $r=p_B-p_A$、$u=v_A-v_B$。两车半径均为 400，首次接触满足 $\lVert r-tu\rVert^2=800^2$。取 $a=u\cdot u$、$b=r\cdot u$、$c=r\cdot r-800^2$。当两车在圆外且正在靠近时，判别式为 $D=b^2-ac$。若 $D\geq0$，较小根可写成 $t=c/(b+\sqrt D)$，避免用两个接近的浮点数相减。只有落在本回合剩余时长内的根才是事件。

碰撞时取从 A 指向 B 的单位法线 $n$，令 $f=(u\cdot n)/(1/m_A+1/m_B)$。对于相向接触，实际法向冲量为 $J=f+\max(120,f)$。于是 $v'_A=v_A-Jn/m_A$，$v'_B=v_B+Jn/m_B$。四车共有六对候选，先处理最早一次接触，再重算剩余时间里的碰撞。检查点沿运动线段检测，可识别同一回合从圆外穿入、再穿出的路线。[物理实现](physics.py) · [边界条件测试](tests/test_physics.py)

例如，两车在同一直线上，初始圆心位于 0 和 1100，速度为 +300 和 −300。半回合后相距 800，等质量对撞后交换速度，剩余半回合各自折返。回合结束时位置回到 0 和 1100，速度为 −255 和 +255。

## 局面评估与双车博弈

完整双车策略把领跑任务和拦截任务分开搜索。领跑车在第 5、9、12 个模拟回合分别计分，权重为 0.1、0.2、1。单个状态既考虑累计赛程和到检查点的直线距离，也估算沿当前速度滑行 2.55 回合后的距离。距检查点不足 2900 时，下一段赛道方向上的速度和朝向开始加分。这使搜索可以接受暂时更远、但出弯速度更好的路线。

拦截车先外推对方领跑车 50 回合，再根据自身惯性、转向时间和加速度估算最早能赶到的交会点。其评分奖励己方进度、惩罚对方进度，并计入与交会点的距离。己队长期没过关时，拦截车改为争取通过自己的下一检查点。对手使用启发式动作，预测不确定性主要来自对方何时转向、开盾或改变分工。

## 实时搜索

| 项目 | Python 单车实验 | C++ 双车竞技策略 |
| --- | --- | --- |
| 计划 | 12 步转向与推力，只执行第一步 | 每车 12 步；先固定队友计划优化领跑车，再用领跑计划优化搭档 |
| 候选 | 每步评估 80 条，保留 5 条优胜计划 | 每车保留 5 条；种子之外两次搜索分别最多 280、200 次迭代 |
| 延续与探索 | 上一回合计划左移；单点交叉、连续 1–3 步变异 | 左移暖启动，定期重新引入启发式计划和交叉；每次变异 1–4 个片段 |
| 目标 | 先比较能否完赛和完赛回合，再比较剩余赛程与速度 | 在同一套四车碰撞仿真里，按领跑、拦截或救场角色评价联合行动 |
| 预算 | 固定评估次数 | 从同一个回合起点累计计时，在 31 ms、53 ms 附近分别停止两次搜索，每 4 次迭代检查时钟 |

官方首回合上限为 1000 ms，常规回合为 75 ms。31 和 53 ms 是搜索截止点，并非实测耗时。固定大小的状态和计划数组、预计算赛段长度、每回合只计算一次拦截参考轨迹，减少了候选评估的重复工作。12 步是当前设置，增大深度会提高每次评估的成本，其净收益取决于固定预算下能探索多少候选。[实验搜索实现](search_demo.py)

## 实验数据

两个固定场景都使用种子 41。两种控制器使用相同物理模型、初始位置和检查点顺序。贪心策略每回合全速瞄准下一检查点。相向场景中，对手按惯性滑行。

| 场景 | 贪心完赛回合 | 搜索完赛回合 | 提前回合 | 观察 |
| --- | ---: | ---: | ---: | --- |
| 正面相向，单检查点 | 24 | 18 | 6 | 搜索在第一回合开盾，承担停推代价后仍更早通过 |
| 无对手，四检查点一圈 | 74 | 55 | 19 | 第 12 回合搜索的剩余路线反而更长，但最终出弯更快 |

在 Windows、Ryzen 7 5800H、CPython 3.12.8 上，以上两个场景各重复 5 次，每场重新用种子 41 初始化搜索器。用单调高精度时钟包裹每次 `Evolution.__call__`，共 365 次决策，P50 为 **11.71 ms**，P95 为 **20.36 ms**，最大值为 **30.13 ms**。这些测量仅覆盖本机的 Python 单车搜索调用。两个固定场景的指标是完赛回合数；对阵胜率见竞技场记录。
